# 무료 운영을 위한 다음 업데이트 계획

2026년 10월 20일 설계를 바탕으로 10월 22일 구현하고 있다. 공개 자료 전용 캐시, 공개 변경 후 갱신, 공통 5분 변경 확인을 검토 브랜치에 구현했다. 관리자 원본 읽기와 저장 충돌 검사는 캐시를 거치지 않는다. 공식 배포는 검토본 확인 후 진행한다. 장기적으로 Hobby 무료 운영을 목표로 하며, 유료 전환이나 다른 서비스 가입은 이 작업에 포함하지 않는다.

## 정지 상태와 작업 범위

2026년 10월 22일 상태 변경: 사용자가 기존 팀의 Pro 무료 체험을 직접 시작했다. 이후 공식 홈페이지 `/`, 공개 작품 API `/api/works`, 관리자 로그인 `/admin/login`을 각각 한 번 조회해 모두 HTTP 200 응답을 확인했다. 공개 작품 API는 125개 작품을 반환했다. 온라인 조회는 복구됐으며, 아래 11월 19일은 체험 시작 전 확인한 차단 해제 예정일이다. 관리자 로그인 성공과 실제 저장은 이번 확인 범위에 포함하지 않았다. 정확한 체험 종료 시각과 결제수단 등록 상태는 아직 확인하지 않았다. 장기 무료 운영 목표는 유지한다.

계정에서 확인한 Blob 차단 해제 예정은 2026년 11월 19일 오후 7시 30분 한국 시간이다. Hobby의 최근 30일 사용량 집계와 Blob의 차단 해제 시점은 구분한다. 해제 예정일에 모든 지표가 정확히 0이 된다고 안내하지 않는다. 기존 파일의 저장 용량도 그대로 남는다.

현재 저장 방식을 유지하는 동안 온라인 관리자 저장과 원본 자료 읽기는 차단의 영향을 받는다. 코드 수정, Git 이력 관리, 로컬 검수는 가능하다. Blob만 차단됐다고 모든 배포 권한이 정지됐다고 판단하지 않는다. 다만 원본에 의존하는 코드를 다시 배포해도 사이트 오류는 해결되지 않는다.

해제 전 무료 복구 후보는 사용자가 확인한 공개 자료만 포함한 읽기 전용 배포다. 최신 공개본과 백업을 대조한 뒤 별도로 승인받는다. 임시저장한 흐름, 비공개 작품, 편집 이력, 로그인 설정은 포함하지 않는다. 별도 무료 저장소로의 이전은 후속 선택지이며, 새 저장소를 만들어 기존 팀의 사용량 제한을 피하려고 시도하지 않는다.

## 현재 조회가 늘어나는 경로

작품 외 화면 하나에서 변경 확인을 한 시간 수행하면 120번의 확인과 문서 720회 읽기가 발생할 수 있다. 초기 표시, 화면 이동, 관리 작업은 이 계산에 포함하지 않는다. 이 계산만으로 실제 사용량 전체를 특정 화면이나 이용자에게 배분하지 않는다.

## 권장하는 공개 자료 읽기 방식

1. 관리자 편집용 원본과 방문자에게 보낼 공개 자료를 분리한다. 공개 자료는 현재 게시한 작품, 분류, 글, 소개, 소식, 전시, 글꼴 중 필요한 필드만 명시적으로 선택한다. 원본 문서 전체를 그대로 캐시하거나 공개 응답으로 내보내지 않는다.
2. Next.js 15.5에서 사용할 수 있는 서버의 지속 캐시를 공개 자료에 적용한다. 브라우저 하나나 서버 프로세스 하나의 메모리만 재사용하는 방식으로 끝내지 않는다. 프로덕션과 각 검토 브랜치의 저장소 범위를 캐시 키와 무효화 태그에 포함한다.
3. 공개 자료는 방문 때마다 Blob에서 다시 읽지 않는다. 정상적인 변경은 관리자 저장 또는 공개 동작이 성공한 뒤 해당 자료의 캐시만 갱신 대상으로 표시한다. API별로 현재 즉시 공개인지 임시저장인지 확인하고 기존 경계를 유지한다.
4. 버전 확인은 캐시한 공개 자료의 버전을 사용한다. 확인할 때마다 archive, about, texts, news, exhibitions, appearance를 다시 읽지 않는다. 버전에는 비공개 변경을 반영하지 않는다.
5. 자동 확인 간격은 우선 5분으로 설계한다. 숨겨진 화면과 오프라인 상태에서는 중단하고, 실패하면 간격을 늘린다. 동일 브라우저의 중복 확인도 줄인다. 방문자는 알림을 눌렀을 때 새 자료를 적용하며 현재 탐색 위치를 임의로 바꾸지 않는다.
6. 초안 저장은 공개 캐시를 갱신하거나 공개 버전을 바꾸지 않는다. 대표 이미지 전용 공개는 대표 설정만 반영하고, 임시저장한 시퀀스와 미공개 캡션을 보존한다.
7. 삭제나 공개 취소를 실행한 경우 관련 상세 화면과 파일 접근까지 함께 갱신한다. 오래된 캐시가 철회한 자료를 다시 노출하지 않는지 확인한다.

관리자 저장 화면에는 변경한 내용을 즉시 반영한다. 새 방문자가 보는 반영 시간과 이미 관람 중인 사람이 알림을 받는 시간은 따로 측정한다. 5분은 알림 확인 간격에 대한 설계값이며, 관리자 저장 지연을 뜻하지 않는다. 실제 반영 시간은 검토 배포에서 확인한 뒤 안내한다.

## 저장 정확성과 장애 대응

- 관리자 저장과 충돌 검사는 원본의 최신 revision과 강한 ETag를 사용한다. 캐시한 공개본의 ETag로 관리자 변경을 저장하지 않는다.
- 비밀번호, 세션, 권한 검사, 관리자 응답은 공개 캐시에 넣지 않는다. 저장소가 막히면 관리자 쓰기를 명확히 차단하고 성공했다고 표시하지 않는다.
- 원본 저장과 공개본 생성이 별도 단계라면 부분 성공을 숨기지 않는다. 원본 저장 성공 뒤 공개 반영에 실패했을 때 원본을 다시 덮어쓰지 않고 공개 반영만 재시도할 수 있게 한다.
- 원본과 공개본의 버전을 함께 검증한다. 동시에 두 번 공개하거나 생성에 실패했을 때 이전 공개본과 새 공개본을 섞지 않는다.
- 마지막 공개본은 별도로 보관한다. 단순히 캐시가 남아 있을 것이라고 기대하지 않는다. 캐시가 비어 있는 새 배포와 새 실행 환경에서도 장애 대응이 작동해야 한다.
- 장애용 사본은 공개해도 되는 자료만 검사해서 만든다. 공개 취소와 파일 회수 정책을 정하기 전에는 오래된 사본을 자동으로 재공개하지 않는다. 정지 전 백업을 전체 최신 원본이라고 간주하지 않는다.
- 장애 상태에서 요청마다 여러 번 재시도하지 않는다. 실패 횟수와 복구 대기 시간을 제한해 연쇄 조회를 줄인다.

## 무료 범위 검수 기준

목표는 통제된 로컬 비교에서 반복 열람의 Blob 원본 조회를 기존보다 90% 이상 줄이는 것이다. 무료 한도 내 운영을 보장하는 수치가 아니며 실제 방문량, 캐시 초기화, 지역, 배포 횟수, 관리 작업에 따라 사용량이 달라진다. Blob 이외의 실행 시간, 캐시, 전송량과 이미지 처리 한도도 함께 확인한다.

- 동일 자료를 반복 열람할 때 캐시를 처음 채운 뒤 원본 조회가 계속 늘어나지 않는지 계측한다.
- 방문자 100명이 버전 확인을 해도 각 확인이 문서 6회 읽기로 이어지지 않는지 확인한다.
- 두 편집자가 저장할 때 충돌을 계속 감지하는지 확인한다.
- 초안 저장 후 공개 화면이 그대로이며, 대표 이미지만 공개해도 비공개 흐름이 나오지 않는지 확인한다.
- 새로고침과 화면 이동 후 글꼴, 작품 순서, 그룹과 선, 좌표가 유지되는지 확인한다.
- 삭제와 공개 취소 후 이전 캐시와 장애용 사본이 해당 자료를 재노출하지 않는지 확인한다.
- 원본을 403 상태로 모의해 공개 화면과 관리자 로그인 화면을 검사한다. 쓰기를 성공 처리하거나 빈 초기 데이터로 원본을 덮어쓰면 실패다.
- 캐시가 전혀 없는 실행 환경과 새 배포에서도 마지막 공개본 처리 방식을 확인한다.
- 배포 후 24시간과 7일 시점의 조회량으로 최근 30일 예상치를 계산한다. 조회량 확인을 위해 별도의 잦은 저장소 순회를 만들지 않는다.

## 구현 순서

1. 원본 조회 횟수를 셀 수 있는 로컬 검수 장치를 준비한다.
2. 공개 자료 전용 읽기와 캐시 범위, 버전 응답을 구현한다.
3. 각 저장과 공개 API의 캐시 갱신 처리를 연결하고 권한과 공개 경계를 검수한다.
4. 공통 변경 알림과 중복 조회, 재시도 제어를 연결한다.
5. 공개 자료 사본과 장애 대응을 구현하고 백업과 복구를 확인한다.
6. 로컬 확인 후 온라인 검토본을 제공한다. 정환님이 확인한 뒤 공식 배포한다.

## 관리자 방문 통계 추가 계획

2026년 10월 20일 요청한 계획이다. 수집기나 관리자 메뉴는 아직 구현하지 않는다. 방문마다 Blob 문서를 읽거나 덮어쓰는 카운터는 만들지 않는다. Google Analytics 표준 무료 통계와 Data API를 후보로 삼고, 정환님 소유 계정의 연결과 읽기 권한을 확인한 뒤 구현한다. 유료 Analytics 360, 광고 연동, 유료 데이터 내보내기는 기본안에 포함하지 않는다.

관리자 메뉴에 방문 통계를 두고 일별, 월별, 연별 그래프와 이전 같은 기간 비교를 제공한다. 기본은 방문자 수, 보조는 방문 횟수와 페이지 조회수다. 방문자 수는 브라우저 식별을 바탕으로 한 추정치다. 일별 고유 방문자 수를 더해서 월간이나 연간 고유 방문자 수로 표시하지 않는다. 같은 전체 기간으로 API에 요청해 중복을 제거한다.

미리보기 배포, 로컬 서버, 관리자와 비공개 미리보기 경로에서는 수집하지 않는다. 관리 기기마다 이 브라우저 집계 제외 설정을 제공하고, 로그아웃 후에도 제외를 유지한다. 검수용 브라우저는 공개 사이트를 열기 전에 이 설정을 적용한다. 관리자 페이지를 방문한 사실만으로 과거 방문을 소급해서 제외했다고 표시하지 않는다. 다른 기기, 새 브라우저, 시크릿 창, 쿠키 삭제 후에는 다시 제외 설정이 필요하다. 공용 와이파이의 IP 전체를 제외하는 방식은 기본으로 쓰지 않는다.

기준 시간대는 한국으로 맞춘다. 월중과 연중 비교는 지난달이나 지난해 같은 경과 기간과 비교한다. 일별 그래프에는 7일 평균을 추가할 수 있으며, 전시나 발표 날짜를 표시할 수 있게 한다. 통계 미수집, 사이트 장애, 처리 대기와 실제 0명을 구별한다. 데이터가 적을 때 증가나 감소를 단정하지 않는다.

통계 보고서는 로그인한 관리자만 읽는다. 외부 통계 API 응답을 재사용하고, 초마다 새로 조회하지 않는다. 최근 날짜는 잠정치로 표시하며 마지막 갱신 시각을 함께 보여준다. Google의 처리에 24~48시간이 걸릴 수 있다. 수집을 시작하기 전 기록은 기존 통계가 없는 한 복원할 수 없다. 광고 차단과 식별 방식 때문에 정확한 사람 수를 보장하지 않는다.

월별과 연별 비교는 집계 보고서를 사용하며, 사용자별 원시 이벤트 보존 기간과 혼동하지 않는다. 장기 집계의 내보내기와 백업 방식도 구현 때 정한다. 통계 페이지에서 오류가 나도 작품 열람과 관리자 편집은 계속 작동해야 한다.

검수 방문을 방문 통계에서 제외해도 실제 Blob 조회는 Vercel 사용량에 포함된다. 방문 통계와 저장소 사용량을 별도로 설명한다. 저장소 사용량 표시를 추가하려면 무료 계정에서 읽을 수 있는 관리 API와 갱신 비용을 먼저 확인한다.
