# Archive 2.0 · 검토 중

이 브랜치는 운영 배포 전 검토용이다. 정식 2.0.0 배포 횟수에 포함하지 않는다.

## 합의한 화면

- WORKS 보기 순서: Cosmos / 천체 → Ecosystem / 생태계 → Strata / 지층 → Sequences / 흐름 → Years / 연도. `/works`의 기본 화면은 Ecosystem.
- 기존 백색 배경 `#F5F5F5` 유지. Cosmos만 어두운 배경. 워터마크와 공개 태그명 제거.
- Ecosystem은 작품 썸네일과 분명한 관계선. 겹침을 줄이고 별도 자리에서 커서 미리보기. 클릭하면 작품 팝업.
- 천체 배경은 `#080A10`, 중심의 옅은 빛은 `#19212C` 약 33% 투명도, 선은 `#DCE2EF` 기본 18% / 강조 76%. 별은 작품 대표색의 색상 계열을 유지하면서 어두운 배경에서 보이도록 밝기만 보정.
- Cosmos는 중앙 여백이 있는 불규칙한 3D 원반. 오른쪽 위로 기울어지고 약 4분에 한 번 회전. 커서를 올리면 회전 중지, 직접 조작하면 자동 재개하지 않음. 전체 관계선은 희미하게, 해당 작품의 관계는 진하게. 서로 다른 그룹을 강제로 연결하지 않음.
- Strata는 연속 색 순서와 치수 비례를 함께 고려. 작은/큰 작품의 표시 크기를 제한하고 원래 이미지 비율 유지. 최소 간격 휴대폰 4px, PC 6px. 공개 시 두 화면 크기의 배치를 계산하여 저장.
- Sequences는 제작연도와 별개의 의미 순서. 단계와 한영 이름을 설정.
- 첫 화면은 6초 순환 슬라이드쇼. 수동 조작 후 자동 재개하지 않음. 마지막/첫 이미지가 바로 이웃함.
- TEXTS: Artist’s Notes / Studies. 언어별 제목·본문·PDF·공개 상태. 문단 종류, 정렬, 크기, 색을 편집. 일반 본문 복사 제한은 완전한 복제 방지 기능이 아님.
- CV: Projects와 항목/기록 순서 관리. 순서는 한영 공통, 내용은 언어별.
- 작업 갈래 확대와 본격적인 모바일·iPad 공간 탐색 개편은 보류. 공통 팝업·간격·관계선·하단 정보 정리는 이번 범위.

## 운영 데이터 보호

1. Cloudinary의 이미지 원본은 그대로 보관한다. 새 이미지와 PDF는 고유 경로로 등록한다.
2. JSON 자료는 PRIVATE Vercel Blob 사본으로 옮긴다. 기존 public 파일에 쓰지 않는다.
3. 저장 시 원본 버전을 확인하는 `ifMatch`를 사용한다. 충돌하면 다시 읽어 병합하거나 사용자에게 재편집을 요청한다. 읽기 실패 때 오래된 예비 파일로 운영 자료를 덮어쓰지 않는다.
4. 저장 전 이전 문서를 비공개 history 경로에 보관한다. 작품 제거는 복구 가능한 보관 처리이다.
5. 작품·분류는 임시 저장과 공개 스냅샷을 분리한다. 초기화 전에 관계 백업을 남기고, 준비될 때까지 이전 공개 화면을 유지한다.
6. 공개 API와 서버에서 전달하는 작품 자료 모두에서 태그명과 비공개 글을 제거한다. 공개 PDF는 공개된 글에 연결된 파일만 열 수 있다.
7. 기존 비밀번호/해시를 그대로 옮긴다. 12시간의 서명된 관리자 세션과 요청 출처 검사. 기존 쿠키는 새 로그인에서 다시 발급한다.
8. PRIVATE 저장 공간 토큰과 세션 서명 키는 Vercel 비밀 설정에만 둔다. 코드·문서·채팅에 값을 기록하지 않는다.
9. Vercel Preview는 브랜치별 저장 경로를 사용한다. 저장 공간 미연결 상태에서는 저장소 자료를 읽는 검토 화면만 제공하고, 저장은 차단한다.
10. 로컬은 `.archive-local/`의 독립 사본을 사용한다. 로컬 서버를 운영 저장 공간에 연결하지 않는다.

## 배포 전 필요한 연결

- 같은 Vercel 계정에 PRIVATE Blob store를 준비하고 전용 토큰을 `ARCHIVE_BLOB_READ_WRITE_TOKEN`으로 연결.
- `ADMIN_SESSION_SECRET`: 별도 생성한 32자 이상 비밀 값. 기존 관리자 비밀번호는 바꾸지 않는다.
- 기존 Cloudinary / Resend 설정 유지. `ARCHIVE_STORAGE=local`과 `LOCAL_ADMIN_PASSWORD`는 Vercel에 설정하지 않는다.
- 기존 관리자 편집을 잠시 멈춘 상태에서 백업/대조한다. 저장소의 101점 예비 자료로 운영 125점을 대체하지 않는다. 실제 수량은 이관 직전에 다시 확인한다.
- `scripts/migrate-archive.ts`는 기본 동작이 읽기 전용 백업이며 `--apply`를 줬을 때만 새 PRIVATE 경로에 사본을 생성한다. 기존 경로를 덮어쓰거나 삭제하지 않는다. 토큰은 환경 변수로 전달한다.
- 먼저 `--scope preview --branch codex/archive-2.0` 사본으로 이미지·PDF 업로드, 로그인, 동시 저장, 공개/임시 상태, 실제 반영 시간을 확인한다.
- 운영용 사본 검증 후 main 반영과 운영 배포를 진행한다. 기존 파일의 보관/정리는 별도 확인 후 진행한다. 특히 과거 공개 경로의 관리자 설정과 태그 자료는 새 API를 막는 것만으로 과거 URL 접근이 사라지지 않는다.
- 롤백 시 이전 코드가 보는 예전 public 저장 경로와 새 데이터의 차이를 먼저 검토한다. 새 저장 내용을 버리고 코드만 되돌리지 않는다.

- 운영 자료를 복사한 공개 검토용 `preview_archive.json`은 이미 공개된 작품 정보와 빈 그룹 이름만 담는다. 백업·관리자 설정·비밀번호·내부 태그명은 포함하지 않는다.

저장소 예비 관리자 설정에서 과거 비밀번호 해시를 제거했다. 실제 관리자 비밀번호 해시는 독립 백업과 PRIVATE 이관 자료에 보존하며 변경하지 않는다. 이전 Git 기록과 과거 public Blob URL의 노출 문제는 이 변경으로 소급 제거되지 않는다.

GitHub 업로드: Mac의 Git 자격 증명은 없고, 연결된 GitHub의 Git tree 생성 요청도 `403 Resource not accessible by integration`으로 거절됨. 따라서 원격 브랜치·PR은 아직 생성하지 않았다. 로컬 `codex/archive-2.0`에 검토용 커밋을 보관한다. GitHub 저장소 쓰기 권한 확인 후 동일 브랜치를 올려 PR을 만든다.

추가 점검: Vercel에 등록된 환경 변수 이름에서 `RESEND_API_KEY`, `CONTACT_TO_EMAIL`을 확인하지 못했다. Contact의 이메일 링크와 별도로 문의 양식은 이 두 설정을 필요로 한다. 외부로 시험 메일은 보내지 않았다. 새 저장소 연결 뒤 배포 전 설정 상태를 다시 확인한다.

검토 전용 PRIVATE Blob `jungwhan-archive-review`를 만들고 Preview/Development에만 `ARCHIVE_BLOB_READ_WRITE_TOKEN` 이름으로 연결했다. 연결 변경 미리보기에서 기존 환경 변수 제거가 0개임을 확인했다. 기존 `BLOB_READ_WRITE_TOKEN`과 Production 설정은 유지한다. 읽기 전용 원본 7개 문서가 백업 후 바뀌지 않은 것을 대조한 뒤 새 저장소에 검토용 10개 문서를 복사하고 검증했다.

새 `ADMIN_SESSION_SECRET`는 Preview에만 추가했다. 원격 브랜치가 아직 없어 Git 브랜치 한정 추가는 거절되어, Preview 기본값으로 설정했다. CLI 검토 배포는 `ARCHIVE_PREVIEW_BRANCH=codex/archive-2.0`을 명시하며, 브랜치가 없는 검토 환경은 저장소에 접근하지 않는다. 기존 관리자 비밀번호는 변경하지 않는다.

`.vercelignore`로 비밀 설정·비공개 백업·로컬 자료·빌드 산출물을 제외했다. 배포 입력 목록 178개를 검사하여 이 파일들이 포함되지 않은 것을 확인했다.

실제 검토 배포에서 저장 실패를 재현했다. Blob 다운로드가 압축되면 약한 HTTP ETag(`W/…`)가 반환되어 조건부 저장이 계속 충돌했다. 자료 읽기에서 비압축 응답을 요청하도록 고쳤으며, 약한 ETag는 저장에 사용하지 않도록 검사한다. 실제 저장소 읽기에서 강한 ETag가 반환되는 것을 확인했다.

수정 후 실제 PRIVATE 저장소에서 두 건을 동시에 기록해 모두 유지되는 것을 확인했다. 과거 버전으로 덮어쓰는 요청도 거절했다. 이 수정부터 검토본 버전은 `2.0.0-preview.2`로 기록한다.
